# Lab: Background Tasks（中等）

## 背景

s07 的任务系统解决了持久化，但所有命令都是同步阻塞的——`bash` 执行时整个 agent 停住等结果。如果要跑一个耗时 60 秒的编译或测试，agent 只能干等。

解决方案：**后台执行**。把长耗时命令丢到后台线程，立即返回一个 task_id，agent 可以继续做其他事。后台任务完成后，结果通过通知队列注入到下一轮 LLM 调用之前。

```
Main thread                Background thread
+-----------------+        +-----------------+
| agent loop      |        | task executes   |
| ...             |        | ...             |
| [LLM call] <---+------- | enqueue(result) |
|  ^drain queue   |        +-----------------+
+-----------------+

Timeline:
Agent ----[spawn A]----[spawn B]----[other work]----
               |              |
               v              v
            [A runs]      [B runs]        (parallel)
               |              |
               +-- notification queue --> [results injected]
```

核心思想：**Fire and forget — agent 不阻塞等命令执行完。**

---

## 你的任务

在 s07（任务系统）的基础上，新建 `my-agents/s08.py`，实现一个 `BackgroundManager` 类和 2 个后台工具，并修改 `agent_loop` 在每轮 LLM 调用前注入后台通知。

---

## Part 1：BackgroundManager 基础结构（简单）

实现 `BackgroundManager` 类的 `__init__`：

- `self.tasks = {}` — 存储后台任务状态，格式 `{task_id: {"status": ..., "result": ..., "command": ...}}`
- `self._notification_queue = []` — 已完成任务的通知队列
- `self._lock = threading.Lock()` — 线程锁，保护通知队列

**提示：**
- `threading.Lock()` 用于多线程安全——主线程和后台线程可能同时读写通知队列
- `import threading` 和 `import uuid`

---

## Part 2：run 方法 — 启动后台任务（中等）

实现 `run(command)` 方法：

1. 生成一个短 ID：`str(uuid.uuid4())[:8]`
2. 在 `self.tasks` 里记录初始状态 `{"status": "running", "result": None, "command": command}`
3. 创建一个 `threading.Thread`，目标函数是 `self._execute`，参数是 `(task_id, command)`
4. 启动线程，**立即返回** task_id（不等线程结束）

**提示：**
- `threading.Thread(target=self._execute, args=(task_id, command), daemon=True)`
- `daemon=True` 表示主程序退出时后台线程自动终止
- 返回值是字符串，例如 `"Background task abc12345 started: sleep 10"`

---

## Part 3：_execute 方法 — 线程执行体（中等）

实现 `_execute(task_id, command)` 方法，这是后台线程实际运行的函数：

1. 用 `subprocess.run()` 执行命令（timeout 建议 300 秒）
2. 更新 `self.tasks[task_id]` 的 status 和 result
3. 把完成通知推入 `self._notification_queue`

**提示：**
- 推入通知队列时必须用 `with self._lock:` 加锁
- 通知内容包含 `task_id`、`status`、`command`（截断）、`result`（截断）
- 用 `try/except` 处理 `TimeoutExpired` 和其他异常

---

## Part 4：check 和 drain 方法（简单）

实现两个查询方法：

1. `check(task_id=None)` — 如果传了 task_id，返回该任务的状态和结果；如果不传，列出所有后台任务
2. `drain_notifications()` — 取出通知队列里的所有通知并清空队列，返回列表

**提示：**
- `drain_notifications` 也需要 `with self._lock:` 加锁
- 先 `list()` 拷贝一份，再 `clear()` 清空原队列

---

## Part 5：修改 agent_loop — 注入通知（中等/困难）

这是 s08 的核心改动。在 `agent_loop` 里，**每次调用 LLM 之前**：

1. 调用 `BG.drain_notifications()` 取出所有后台通知
2. 如果有通知，拼接成文本，以 `<background-results>` 标签包裹
3. 注入两条消息：一条 `user` 消息（通知内容），一条 `model` 消息（确认收到）

**提示：**
- 注入格式：`{"role": "user", "parts": [types.Part(text="<background-results>\n...\n</background-results>")]}`
- 紧跟一条：`{"role": "model", "parts": [types.Part(text="Noted background results.")]}`
- 为什么要两条？因为 Gemini API 要求 user/model 交替，不能连续两条 user

---

## Part 6：注册工具（简单）

在 `TOOL_HANDLERS` 和 `TOOL_DECLARATIONS` 里注册 2 个工具：

- `background_run` — 必填 `command`（string），描述要说明是非阻塞的
- `check_background` — 可选 `task_id`（string），省略时列出全部

## 验证

```sh
python my-agents/s08.py
```

测试 1 — 后台执行不阻塞：
```
Run "sleep 5 && echo done" in the background, then immediately run "echo hello" with bash
```
预期：`background_run` 立即返回 task_id，`bash echo hello` 也立即返回，不用等 5 秒。

测试 2 — 检查后台任务：
```
Check all background tasks
```
预期：刚启动的可能还是 `running`，等几秒再查应该变成 `completed`。

测试 3 — 通知注入：
```
等 5 秒后随便说一句话
```
预期：LLM 调用前会收到 `<background-results>` 注入的完成通知，模型会告诉你后台任务已完成。
